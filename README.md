# Эталон Ковка — витрина кованых изделий

Премиальная витрина декоративных кованых изделий с тёмным люкс-дизайном. Сайт работает как **витрина-лидогенератор**: пользователь подбирает элементы в каталоге и отправляет заявку напрямую в WhatsApp/Telegram, оплата — через Kaspi после согласования.

**Сайт:** [etalon-kovka.kz](https://etalon-kovka.kz)

## Стек

- **Vue 3** (Composition API, `<script setup>`)
- **Pinia** (state management)
- **Vue Router 4** (history mode, lazy-загрузка роутов)
- **Tailwind CSS 4** (utility-first + `@theme` переменные)
- **Vite 6** (сборка)
- **PWA** — `manifest.webmanifest` + service worker

## Установка и запуск

```bash
npm install
npm run dev      # dev-сервер на localhost:5173
npm run build    # production-сборка в dist/ (перед сборкой генерируется sitemap.xml)
npm run build:static # диагностическая сборка без HTML страниц (не для публикации)
npm run preview  # предпросмотр production-сборки
npm run preview:cloudflare # локальная проверка заголовков, redirect и HTTP 404 на Wrangler
npm run lint     # ESLint
npm test         # регрессионные тесты (node --test)
npm run test:e2e # Playwright E2E по критическим сценариям
npm run format   # Prettier
```

Требуется Node.js 24 LTS. Команды `dev`, `test` и обе сборки автоматически создают уменьшенные версии фотографий и маленький favicon. Производные файлы в `public/images/optimized/` и `src/data/image-variants.json` не хранятся в Git; оригиналы остаются в каталоге для увеличения. После замены фото варианты пересоздаются с новым хешем.

Полная сборка в Cloudflare Workers Builds использует закреплённый Chromium без системной установки зависимостей. Эта же ветка запуска проверяется в GitHub Actions. Для публикации требуется `npm run build`; `build:static` не создаёт HTML страниц и применяется только для диагностики.

## Функционал

### Каталог

- **10 категорий**, **347 товаров** с фото, материалом, описанием и доступными размерами и весом
- Фильтрация по категории и поиск по названию и описанию
- Поиск по каталогу (в шапке + на странице каталога)
- Пагинация (20 товаров на страницу)
- Цены — по запросу (`hidePrice`). 175 позиций добавлены из прайса от 13.07.2026 без переноса цен (`price: null`); сверка всех 344 строк — `docs/catalog-import-2026-07-13.json`.

### Заявки и оплата

Сайт НЕ содержит онлайн-корзины и онлайн-оплаты — всё через мессенджеры:

- **Заявка по товару** → WhatsApp / Telegram с предзаполненным сообщением
- **Форма на странице контактов** → предзаполняется из `?product=<id>`
- **Оплата через Kaspi** — после подтверждения наличия, количества и доставки
- `/cart`, `/checkout`, `/wishlist` редиректят на каталог/контакты (сохранили SEO-чистоту и внешние ссылки)

### Прочее

- Блок «Способы применения» — 5 фото-примеров с hover-эффектами
- Недавно просмотренные товары (`localStorage`)
- SEO: динамические `<title>`/`description`, canonical, JSON-LD (Product/Organization/ItemList), prerender indexable-страниц, `sitemap.xml`, `robots.txt`
- Доступность: skip-link, ARIA-атрибуты, `prefers-reduced-motion`
- PWA/service worker: hashed JS/CSS чанки витрины добавляются в precache при build. Конструктор и голосовой помощник загружаются при открытии соответствующей функции. HTML использует network-first, изображения и manifest — stale-while-revalidate, hashed JS/CSS — cache-first. Сбой необязательной иконки не мешает установке; отсутствие обязательного HTML/чанка отклоняет новую установку и сохраняет прежний worker.
- Плавающий блок мессенджеров + нижняя мобильная навигация

### Конструктор ковки

Конструктор доступен по адресу [`/constructor`](https://etalon-kovka.kz/constructor) через меню сайта на компьютере и телефоне. Маршрут включён в production-сборку и загружается отдельно при открытии; сборка создаёт его HTML-страницу, canonical и запись в sitemap. Конструктор работает без ИИ и внешних сервисов. Для локальной разработки: `npm run dev -- --host 127.0.0.1 --port 5173`, затем открыть [локальный конструктор](http://127.0.0.1:5173/constructor).

- Ворота, калитка и одна повторяемая секция забора; габариты в миллиметрах.
- Все 347 товаров из 10 категорий каталога: поиск по названию, артикулу и профилю, фильтр категории и проверка подходящего размера. Доступны перемещение, поворот, отражение, копирование и равномерное распределение.
- Детали с неполными или противоречивыми габаритами отмечены «Уточнить размеры». Их можно добавить в список для обсуждения с мастером без размещения на размерном эскизе. Если размеры известны, доступен ручной ввод ширины и высоты одной детали в ориентации фото. Эти размеры сохраняются в проекте; изменение рамы их не растягивает.
- Парные товары размещаются по одной детали. Комплектация показывает нужное количество целых пар и остаток; округление выполняется один раз по артикулу с учётом числа секций.
- Галерея «Готовые композиции»: Шанырак, Тихий ритм, Бабочка, Волна, Парадный, Лира, Двойная вязь, Розетка. Превью показывают реальные детали при выбранных габаритах; неподходящие рисунки указывают минимальный размер. Применение заменяет рисунок одним отменяемым действием, после него все детали можно редактировать.
- Предупреждения о выходе за раму и пересечении стыка створок; рама условная, изготовление проверяет мастер.
- Количество для забора умножается на число секций. Скрытые цены не выводятся.
- Отмена/повтор, автосохранение и до 20 именованных вариантов с миниатюрами в этом браузере. Старые JSON-проекты продолжают открываться. «Подготовить подборку для мастера» объединяет эскиз, размеры, комплектацию, комментарий и позиции на уточнение: PNG, печать / сохранение PDF, текст, файл для продолжения редактирования и открытие WhatsApp с подготовленным сообщением. Изображение прикладывается вручную; автоматической отправки нет. Экспорт включает весь эскиз независимо от увеличения и положения обзора.
- Поворот на чертеже: выделить деталь и потянуть круглую ручку над ней мышью или пальцем; Shift фиксирует шаг 15°. На ручке доступны стрелки (1° / Shift 15°). Точный угол также задаётся в поле «Поворот, °».
- «Копия в другой угол» создаёт зеркальный экземпляр слева/справа, сверху/снизу или по диагонали с теми же отступами от рамы. Для ворот можно выбрать текущую створку или всю конструкцию. Исходная деталь остаётся на месте, действие отменяется одним шагом; на телефоне кнопки находятся под чертежом.
- «Выровнять рисунок» открывает предпросмотр горизонтальных рядов, вертикальных колонок и полных сеток. Крайние позиции и область наброска сохраняются; чистые промежутки учитывают повёрнутые габариты и составные узоры. Можно выбрать направление, изменить состав или оставить набор на месте. Неоднозначность, нехватка места и закреплённые детали обозначены до применения. Предпросмотр не меняет проект; применение — один шаг отмены.
- «По центру» — отдельная команда по ширине, высоте или обеим осям реальной створки. «Уголки по раме» имеет свой отступ от внутренней рамы (по умолчанию 20 мм). Геометрия учитывает каркас 40 мм и зазор ворот 24 мм; размер и поворот деталей сохраняются.
- «Во все углы» в настройках выбранного уголка заполняет недостающие углы: 4 угла текущей створки или 8 углов обеих створок ворот. Образец можно добавить в любое место холста. Уже добавленные одинаковые уголки используются в расстановке; недостающие копии отражаются внутрь рамы. Отступ задаётся рядом с кнопкой. Предпросмотр выделяет добавленные и переставленные детали; при невозможности расстановки показывает причину без ложного результата «после». Вся операция отменяется одним действием.
- «Выбрать несколько» или Shift / Ctrl при выборе позволяет объединить детали в узор, повернуть, отразить, переместить или скопировать их вместе. Закрепление находится в дополнительных настройках. Плюс в каталоге сразу добавляет и выделяет деталь в центре створки: дальше её можно перетащить. Сетка и привязка к ней включаются независимо; направляющие показывают центры, края и равные промежутки.
- Canvas кэширует расчёты неизменённых деталей. Распознавание шаблона и автосохранение запускаются после завершённого действия; уход со страницы сохраняет последнее положение, включая незавершённое перемещение. Лимит задаётся в `PROJECT_LIMITS.maxItems`, геометрические операции используют общие границы створок и `src/constructor/geometry.js`.
- На телефоне доступен отдельный рабочий экран с нижними панелями каталога и настроек. Один палец двигает деталь или обзор на пустом месте; два пальца управляют масштабом. «Показать целиком» сбрасывает обзор. Смена основы и повторение левой стороны справа показывают результат до применения; пользовательский рисунок перед сменой основы сохраняется отдельным вариантом.

Метаданные конструктора — `src/data/constructor-elements.json`, основной каталог и оригиналы фото не меняются. Габариты сверены с данными каталога, физический обмер не проводился. Для общих фотографий указан отдельный экземпляр или вид; SVG-маски отделяют перекрывающиеся границы парных деталей. `node scripts/analyze-constructor-images.mjs` выводит границы фотографий для проверки, не изменяя изображения.

### Аналитика

ID счётчиков передаются через переменные **сборки** платформы. Для релиза 1.1.0 одинаковые значения настроены в Cloudflare Workers Builds → Settings → Build → Variables and secrets и GitHub → Settings → Secrets and variables → Actions → Variables. При смене счётчиков обновляйте обе платформы:

- `VITE_GOOGLE_ANALYTICS_ID=G-3TYNDM52D9`
- `VITE_YANDEX_METRIKA_ID=110264764`

GitHub Actions получает их из repository variables; переменные исполнения Worker не заменяют переменные сборки Vite. Для локального запуска скопируйте `.env.example` в `.env.local`, для отдельной production-сборки используйте `.env.production.local`:

- `VITE_YANDEX_METRIKA_ID`
- `VITE_GOOGLE_ANALYTICS_ID`

Файлы `.env.local` и `.env.production.local` остаются исключёнными из Git и используются только для локального запуска и сборки. CI и Cloudflare получают значения из настроек платформы. Проверка SEO после сборки проверяет наличие обоих ID в собранном приложении.

Все значения `VITE_*` доступны в браузере: здесь допустимы публичные ID, но не секреты. Без ID соответствующий счётчик не запускается. См. [переменные Vite](https://vite.dev/guide/env-and-mode) и [настройки Workers Builds](https://developers.cloudflare.com/workers/ci-cd/builds/configuration/).

Счётчики запускаются только после согласия пользователя на cookies/аналитику.
Основные события без персональных данных: `catalog_open`, `product_open`, `contact_form_open`, `lead_scenario_select`, `lead_whatsapp`, `lead_telegram`. Для Google Analytics заявка также уходит как `generate_lead`, а открытие товара — как `select_item`.

## Проверки качества

Математика конструктора и поведение Pinia-стора проверяются прямыми модульными тестами. Поиск, мобильное меню, доступность счётчиков, SEO и BreadcrumbList проверяются в браузере; метаданные дополнительно проверяются в готовом HTML без выполнения приложения. Проверки по тексту исходников заменяются постепенно, при изменении соответствующих функций.

`npm run verify:perf` проверяет размер сборки и загрузку главной страницы. Данные каталога выделены в отдельный `catalog-data`-чанк с лимитом 25 КБ gzip; он также входит в лимит JavaScript витрины 130 КБ. Лимит основного кода приложения остаётся 35 КБ. Для отдельно загружаемого конструктора действуют лимиты 90 КБ JavaScript (редактор — 70 КБ, метаданные — 22 КБ) и 16 КБ CSS. Проверка графа сборки и сетевых запросов подтверждает, что конструктор не загружается на главной, в том числе через service worker.

Компоненты используют Composition API / `<script setup>`. Неиспользуемая поддержка Options API исключена через [флаг сборки Vue](https://vuejs.org/api/compile-time-flags.html#vue-options-api); перед добавлением сторонних Vue-компонентов проверяйте их совместимость.

Основной набор перед пушем:

```bash
npm test
npm run lint
npm run build
npm run test:e2e
git diff --check
```

E2E покрывает критические сценарии: переход в каталог, поиск, карточку товара с SEO/inquiry-ссылками, закрытие поиска по клику вне панели, форму контактов и плавающие мессенджеры.
