# Индексация Google — 23 октября 2026

## Исходное состояние

Данные прочитаны в кабинетах владельца, настройки аналитики не менялись.

- Search Console, 23 сентября — 20 октября: 258 показов, 13 кликов, CTR 5%, средняя позиция 9,2. Главная получила 11 кликов.
- Отчёт индексирования обновлён 16 октября: 43 проиндексированных URL, 319 обнаруженных без индексации, 62 альтернативных с canonical, 28 перенаправлений и 1 просканированный без индексации. Альтернативные адреса и перенаправления не считаются автоматически ошибками. Эти числа относятся ко всем обработанным адресам, а не только к sitemap.
- Sitemap успешно обработан 17 октября: 363 URL.
- GA4, 25 сентября — 22 октября: 5 пользователей, 5 сеансов, 26 просмотров, 45 событий; `generate_lead` отсутствует. Эти данные не подтверждают отсутствие реальных обращений: измерение зависит от согласия на cookies и требует отдельной проверки.

Публичная проверка перед выпуском: `/catalog/page/2` возвращает 404, а HTML каталога не содержит ссылок пагинации. Предыдущий полный обход выявил 150 из 347 товаров без входящих HTML-ссылок с других страниц sitemap. Это подтверждённый недостаток перелинковки, но не доказательство единственной причины исключения Google.

## Состав исправления

- Обычные ссылки пагинации вместо переключения исключительно через состояние JavaScript. Оформление и число товаров на странице сохраняются.
- Готовый HTML страниц `/catalog/page/N` и `/catalog/<категория>/page/N`, отдельные title, description и canonical. Страницы 2+ не канонизируются на первую.
- Все 347 товаров доступны от главной по HTML-ссылкам. Сборка проверяет также достижимость всех адресов sitemap, чтобы исключить повторное появление изолированных страниц.
- Sitemap расширен до 393 индексируемых URL. Даты `lastmod` берутся из истории изменений исходных файлов, а не подменяются датой каждой сборки.
- Уникальные метаданные товаров с одинаковыми названиями, метаданные 10 категорий и контактов. Видимые названия, описания, счётчики и дизайн не переписываются.
- Постоянные редиректы вариантов `/page/1` и завершающего слеша; реальные HTTP 404 у несуществующих страниц. ItemList соответствует видимым товарам текущей страницы.

## Выпуск и проверка

Выпуск идёт через PR и обязательные проверки GitHub; Cloudflare публикует только успешный commit ветки `main`. После публикации необходимо проверить HTTP-ответы, sitemap, canonical и граф ссылок опубликованного сайта. До появления исправленных адресов на production запрос переобхода не отправляется.

Затем в Search Console проверить актуальную версию каталога и одной новой страницы пагинации, запросить переобход нескольких важных URL и повторную обработку обновлённого sitemap. Массовые повторные запросы не нужны. Самостоятельно сбрасывать исключения canonical/redirect не требуется.

Google самостоятельно решает, когда обходить и индексировать страницы; исправление не гарантирует индексацию всех товаров и определённые позиции. Основание: [пагинация](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading), [устранение проблем обхода](https://developers.google.com/search/docs/crawling-indexing/troubleshoot-crawling-errors), [запрос переобхода](https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl).

Отслеживать результат по отчёту индексирования после его обновления и по одинаковым завершённым периодам Search Console. Исходные данные разных периодов GA4 и Search Console напрямую не сравнивать.
