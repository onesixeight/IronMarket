## Исправления

### Пагинация и внутренняя перелинковка — высокий приоритет

Раньше переход на следующую страницу менял только состояние приложения. В HTML не было ссылки с адресом следующей страницы. Добавлены адреса `/catalog/page/2` и `/catalog/<категория>/page/2` и обычные ссылки на номера, предыдущую и следующую страницы. Каждая страница получает готовый HTML, свой title, description и canonical, включается в sitemap. Перезагрузка и история браузера сохраняют номер страницы.

Первый экран сохраняет прежние адреса `/catalog` и `/catalog/<категория>`. Варианты `/page/1` постоянно перенаправляются на них. Несуществующие номера страниц получают настоящий HTTP 404 на используемом Cloudflare-хостинге; ссылки на такие страницы не генерируются. Фильтрация на второй и последующих страницах возвращает адрес к `/catalog`; существующие поиск и фильтры сохраняют работу.

Подход соответствует [рекомендациям Google по пагинации](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading): отдельные адреса, доступные через `<a href>`, и собственные canonical.

### Метаданные — средний приоритет

У двух товаров «Мираж» и двух товаров «Бабочка» совпадали title. У двух других пар совпадали description. Метаданные карточек теперь включают название и артикул, различая похожие товары. Видимые названия товаров и данные каталога сохранены. Title и description каталога уточняют ассортимент, Астану и поставку по Казахстану.

Canonical и `og:url` обновляются от реактивного маршрута, включая переход между страницами одного компонента. Для social image убрано общее указание PNG, которое не соответствовало части фотографий товаров.

### Структурированные данные и защита от повторения ошибок

ItemList описывает видимые товары текущей страницы. Расширен `npm run verify:seo`: проверка всех индексируемых HTML, уникальности title/description, единственного корректного canonical и H1, индексируемости, внутренних ссылок, соответствия ItemList и достижимости каждого товара с главной. Добавлены браузерные сценарии пагинации, перезагрузки, истории, фильтрации, redirects, 404 и различимости товаров по артикулам.

## Что уже работало

- Все 363 адреса опубликованного sitemap вернули HTTP 200, собственный canonical и один H1. Содержимое доступно в исходном HTML до исполнения JavaScript.
- `robots.txt` и `sitemap.xml` доступны с HTTP 200. Googlebot, YandexBot и ресурсы каталога не блокируются. Существующая политика доступа AI-краулеров сохранена.
- HTTP и www-варианты домена перенаправляют на основной HTTPS-домен с кодом 301 и сохранением query-параметров.
- Несуществующий адрес возвращает HTTP 404 с `noindex`; старые `/cart` и `/wishlist` перенаправляют в каталог, `/checkout` — в контакты.
- В проверенном HTML нет изображений без атрибута alt. Наличие alt не является оценкой качества описания каждого изображения.
- Есть LocalBusiness, BreadcrumbList, FAQPage и разметка карточек. Телефон, адрес и часы работы берутся из общей конфигурации.
- Публичные ID Google Analytics и Яндекс.Метрики присутствуют в сборке; браузерные тесты проверяют согласие и события заявок. Получение реальных событий в кабинетах не проверялось.
- При цене по запросу карточки используют ItemPage без вымышленных Offer/цен. Это корректно для текущего содержания; расширенные товарные результаты с ценой этой разметкой не заявляются.
